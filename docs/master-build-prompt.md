# Master Build Prompt — Serene Origins

Use this file as the primary execution prompt after reviewing the strategy docs.

## Your role
You are a senior product designer, UX strategist, brand-sensitive copy implementer, and front-end engineer.

You are building a **presentation-ready, production-caliber first pass** of the Serene Origins website.

This is not a brainstorming exercise.
This is a focused build task.

## Read these files first
Before building, review these files in this exact order:

1. `project-brief.md`
2. `brand-strategy.md`
3. `design-direction.md`
4. `sitemap-wireframe.md`
5. `copy-deck.md`
6. `technical-build-spec.md`
7. `assets-content-checklist.md`
8. `review-checklist.md`
9. `../CLAUDE.md`

You must use these documents as the source of truth.

## Build objective
Create a **high-impact landing page** for Serene Origins that is strong enough to present to Levy for review and clean enough to become the production foundation with minimal rework.

## Primary conversion action
All membership CTAs must link to:

`https://buy.stripe.com/aFa7sLbbm8UDfamgUN0gw00`

## What you are building
Build a single premium landing page experience that includes:

- Hero
- Pain / relatability section
- The Serene System section
- What’s included section
- What happens after signup section
- Experience preview section
- Trust / mission section
- Pricing section
- FAQ section
- Final CTA
- Footer

## Core product framing
Serene Origins is a structured support and education experience for people living with herpes who want more clarity, privacy, confidence, and grounded community.

Do not frame it as:
- a generic wellness brand
- a blog
- a medical provider
- a vague “supportive space” with no structure

## Required outcomes
By the time a user reaches the pricing section, they should clearly understand:
- what Serene Origins is
- who it is for
- what they get
- what makes it different
- what happens after signup
- why the membership is worth paying for

## Design standard
The design must feel:

- premium
- private
- calm
- emotionally safe
- structured
- modern
- mobile-first
- polished enough for stakeholder review

The site should look intentional, not template-like.

## UX standard
The page must:
- explain the offer fast
- build trust without heavy-handed disclaimers
- use spacing and hierarchy well
- remove confusion around the user journey
- keep CTA opportunities visible without feeling pushy

## Implementation preference
Preferred stack:
- Next.js with App Router

If the repo already contains a stack, continue in that stack unless it would clearly reduce quality.

## Code expectations
- clean component structure
- semantic HTML
- accessible contrast
- responsive behavior across mobile/tablet/desktop
- tasteful motion only where useful
- no bloated dependency choices unless clearly justified

## Visual direction
Follow the design-direction document.
Favor:
- editorial spacing
- premium cards
- soft gradients
- warm dark surfaces
- elegant typography
- restrained accent use

Avoid:
- generic startup blues
- medical-looking UI
- loud wellness clichés
- overly feminine stereotype styling
- visual clutter

## Copy rules
Use the copy in `copy-deck.md` as the baseline.
You may refine wording for flow and quality, but do not drift from the brand strategy.

Do:
- keep copy clear
- keep it emotionally intelligent
- make the offer tangible
- emphasize privacy, structure, and support

Do not:
- overpromise outcomes
- imply guaranteed medical results
- use manipulative fear tactics
- make the language sound vague or overly poetic

## Experience preview requirement
If final screenshots are not available, create an elegant mock “inside the experience” preview using:
- private discussion cards
- onboarding step cards
- category labels
- blurred or stylized placeholders

This section should still feel premium and believable.

## Pricing requirement
The pricing section must make the offer feel simple and confident:
- $29/month
- clear value stack
- clean CTA to Stripe
- optional short reassurance if accurate, such as cancellation flexibility

## Stakeholder review requirement
Assume Levy will review this visually and strategically.
That means the build must communicate quality immediately, without needing a long explanation.

## Deliverables
Produce:
1. the full landing page implementation
2. reusable components where appropriate
3. a polished visual system
4. working CTA links
5. a responsive experience
6. no broken placeholder logic
7. no empty sections
8. a build that feels ready to demo

## Final self-check
Before stopping, review your work against `review-checklist.md`.

Then make one final quality pass for:
- spacing consistency
- CTA consistency
- mobile polish
- copy clarity
- premium visual feel

## Build now
Do not return a strategy memo.
Do not return a loose concept.
Build the first strong version of the site.
